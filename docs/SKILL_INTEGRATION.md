# 学径 Skill 接入设计

Skill 不等于智能体。它可以只是一个可复用、可验证的学习工作流，也可以成为智能体能够调用的工具包。

## 三种运行层级

1. **确定性 Skill（不需要智能体）**
   - 固定输入、固定步骤和固定输出。
   - 例如：对选中课件执行 OCR、生成页面索引、导出复习清单、按规则安排间隔复习。
   - 由学径本身调用现有本地模块即可。
2. **模型辅助 Skill（需要模型，不需要自主智能体）**
   - 工作流由程序规定，模型只完成其中一个受限步骤。
   - 例如：资料知识点精炼、根据已选资料生成快速测试、将 AI 返回的资料 ID 应用到复习选择。
   - 当前“AI 精炼”已经属于这一层：程序决定输入范围、校验输出和写入位置，模型不能自行调用其他功能。
3. **智能体 Skill（需要智能体运行时）**
   - 智能体可根据目标自主选择 Skill、循环执行工具、读取结果并调整计划。
   - 例如：“检查本周所有 DDL，结合薄弱知识点重新安排三天计划，并生成待确认事项”。
   - 这类能力需要 OpenClaw、AstrBot、Hermes、Agents SDK 或学径未来自己的受控智能体层。

## 推荐的 Skill 包结构

```text
skill-name/
  manifest.json      # 名称、版本、输入输出、权限声明
  SKILL.md           # 面向模型或用户的工作流说明
  prompts/           # 可选提示词模板
  scripts/           # 可选受控脚本
  assets/            # 可选模板或静态资源
```

学径第一阶段只加载声明式 Skill，不默认执行任意第三方脚本。`manifest.json` 应明确声明是否需要：

- 读取课程元数据；
- 读取选中的资料正文或原件；
- 调用云端 AI；
- 修改复习选择或日程；
- 访问网络；
- 写入资料库。

## 与未来智能体的关系

Skill 注册表应独立于智能体。学径页面、快捷操作中心和未来智能体都调用同一套受控 Skill 接口：

```text
用户 / 快捷操作 / 智能体
        ↓
   Skill 注册表
        ↓
权限确认 → 参数校验 → 执行 → 结果预览 → 用户确认写入
```

这样当前版本可以先使用无需智能体的学习 Skill；未来接入智能体时，不需要重新实现知识库、作业、复习日程和测试工具。

## 安全边界

- Skill 默认不能读取 Blackboard、Gradescope、邮箱或 API 的明文凭据。
- 云端调用必须显示将发送的数据类型；课件原件与本地分页文本分开授权。
- 修改 DDL、复习日程、知识点自评等用户数据前应预览并确认。
- 第三方脚本默认禁用；后续若开放，应使用目录沙箱、权限清单、签名或明确的本地信任开关。
- 智能体只能调用已注册动作，不能获得资料库和系统命令的无限权限。
